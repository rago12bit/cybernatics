# SBOM, signed reports and provenance

## SBOM

```bash
bulwark sbom ./my-project -o sbom.cdx.json
```

Writes a **CycloneDX 1.6** JSON SBOM generated by [Syft](https://github.com/anchore/syft) (image pinned by digest,
run in the same sandbox as every scanner: no network, read-only root, non-root). It lists what the project
contains; it does not judge it, and it is separate from the findings.

- Built from Bulwark's sanitized workspace, so installed dependency directories (`node_modules`, virtualenvs) are
  not included; lockfiles and manifests are. Dev dependencies **are** included, matching the scope Trivy and
  OSV-Scanner scan.
- Verified against the official CycloneDX 1.6 JSON schema on a real project (`tests/integration`).
- CycloneDX 1.6 rather than Syft's newer default (1.7), for the widest tool support.
- In the GitHub Action: `sbom: true` writes it and exposes `sbom-file`.

## Signing a report

You need a cosign key pair, which you create and keep:

```bash
cosign generate-key-pair          # or run cosign's container; writes cosign.key and cosign.pub
export COSIGN_PASSWORD=...        # the key's password; never put it on a command line
bulwark scan ./my-project --format json -o scan.json
bulwark attest sign scan.json --key cosign.key          # writes scan.json.sig.bundle
```

cosign runs in a container with no network and a read-only filesystem; the key is mounted read-only and the password
is passed by name. **No transparency-log entry is made**: the signature proves the holder of the key signed exactly
these bytes, not when. Keyless (OIDC) signing is not implemented.

## Provenance attestation

```bash
bulwark attest provenance scan.json --scan scan.json --key cosign.key \
  --artifact sbom=sbom.cdx.json --source-label owner/repo --commit "$(git rev-parse HEAD)"
```

Produces `scan.json.provenance.bundle`: a signed **in-toto** statement (cosign emits Statement v0.1) whose subject
is the file and whose predicate (`https://github.com/Rag2102/cyberimp/attestations/scan/v1` -- the project's
first repository name, kept as is: it identifies the predicate format, and changing it would make every
attestation made so far stop matching) records:

- the Bulwark version and, per scanner, its image reference, **local image id** (content hash) and status;
- the source label and commit you gave;
- result **counts** (unique, raw, ignored, by severity), never the findings;
- the SHA-256 and size of the report and every `--artifact`;
- the time the attestation was made, and a plain statement of what it does not claim.

## Verifying

```bash
bulwark attest verify scan.json --pub cosign.pub
```

Checks whichever bundles sit next to the file. Exit 0 only if every check passes; a modified file, another key, an
attestation for a different file, or a different predicate type is rejected (all exercised in the integration tests).
It prints the verified predicate summary.

## What this does and does not give you

- **Gives:** evidence that a specific file is the one a holder of your key signed, and a record of which scanner
  builds produced it. Useful for handing a report to an auditor or gating a release on a specific scan.
- **Does not give:** any statement that the findings are correct or complete; protection if the key is stolen;
  a timestamp you can trust (no transparency log); attestation of the scanner *databases* (vulnerability data
  and EPSS/KEV feeds are not recorded); identity beyond "holds this key". Local image ids are only as
  trustworthy as the machine that reported them.
- **Not automated in the action:** signing needs your private key, so it is a step you add yourself with your own
  secret handling.
